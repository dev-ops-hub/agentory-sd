It was built in response to a user-supplied brief naming a "Tester / QA Engineer" role (persona, responsibility boundary vs. `software-engineer`/`frontend-developer`/`devops-engineer`/`security-auditor`, a 32-section workflow spec, and three external repositories to research) — the user explicitly renamed the role `test-engineer` partway through. The brief was decomposed and cross-checked against this repo's existing conventions rather than built from its proposed file tree verbatim; see "Deviations from the brief" below.

## Deviations from the brief

The brief's proposed §6 architecture (10 owned skills + a 14-entry shared-skills list including `unit-testing`, `integration-testing`, `api-testing`, `mocking-and-fixtures`, `accessibility-testing`, `performance-testing` as separate shared skills) was treated as a target shape, not a literal file list, per the brief's own §24 ("avoid skill explosion... prefer one clear concern + progressive disclosure... unless separate skills provide material value") and §6 ("do not create empty placeholder skills... create only useful capabilities"):

- **No separate `unit-testing`/`integration-testing`/`api-testing`/`mocking-and-fixtures` shared skills were created.** This repo already had `software-engineer/skills/testing/test-strategy-and-automation/SKILL.md` covering exactly this ground (AAA pattern, HTTP-layer testing, mocking boundaries, integration tests, contract testing, fixtures) for this project's pytest-flavored stack. It was **moved** to `../shared-skills/test-strategy-and-automation/SKILL.md` (second consumer: `test-engineer`) rather than duplicated into four smaller near-identical skills.
- **No separate `accessibility-testing` shared skill was created.** `ux-designer/skills/a11y-audit/SKILL.md` already does WCAG 2.2/ARIA auditing with real contrast-measurement tooling; `test-engineer` references it directly in place (per this repo's existing `security-auditor/SOURCE.md` convention of reading another agent's owned skill rather than cloning it), scoped to the functional-acceptance slice only (see `test-engineer.md`'s role-boundary box).
- **No `performance-testing` skill was created**, dedicated or shared. No load/throughput threshold exists anywhere in `planning/constitution.md` or the PRD at the time of this change, and the brief's own §14 forbids inventing arbitrary pass/fail thresholds while §6 forbids placeholder skills with nothing to test against. Folded into a short conditional subsection of `skills/test-strategy/SKILL.md` instead, naming k6 as the natural fit for this project's FastAPI backend if/when a real threshold is ever stated.
- **`agent-evaluation` became `agent-regression-evaluation`**, test-engineer-owned rather than shared, since no real external skill by that name was found to adopt (see Research basis above) and judging an agent/prompt change's behavioral regression is a QA judgment call analogous to this agent's other owned skills, not a reusable technical implementation detail multiple agents would consume identically.
- **The role name itself is `test-engineer`**, not "Tester," per the user's explicit instruction overriding the brief's own naming.

## Testing

No baseline (RED) pressure-testing with subagents has been run against any of this agent's 11 owned skills. `defect-triage` is the one skill in this set written with genuine Iron-Law/rationalization-table structure (the "no production-code fixing" rule is a real discipline-enforcing claim, not a reference checklist) — per the Iron Law of `superpowers:writing-skills` itself ("no skill without a failing test first"), a baseline pressure run (a subagent given a trivially-fixable bug, a tight deadline, and high confidence in the one-line fix, with only this skill present) is the natural next step before this rule is treated as load-bearing in a real dispatch. The remaining 10 skills are reference/technique skills (strategy framing, design techniques, report schemas) in the same category this repo's own `software-engineer/SOURCE.md` and `security-auditor/SOURCE.md` already treat as not requiring subagent pressure-testing — written and reviewed for accuracy and scope instead.
