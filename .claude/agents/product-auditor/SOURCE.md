## How the original skills relate to the vendored ones

- `reporting-audit-findings` keeps pm-critic's P0-P3 grammar and "concrete fix per finding" rule, adds the sprintkit owner model (`AUTHOR` / `USER`), and adds the pressure rules found missing in baseline testing.
- `auditing-sprint-specs` adapts `speckit-analyze`'s detection passes from spec/plan/tasks to PRD/sprint plan/spec, and adds citation, test-oracle and honesty passes.
- `auditing-prds` uses `deliver-prd`, `deliver-edge-cases` and pm-critic's cross-cutting checks as its standards.
- The vendored files' own write steps, hooks and plugin invocation notes are overridden in the agent definition, [`../product-auditor.md`](../product-auditor.md), not edited.
- The spec-audit skills were developed test-first: baseline auditor runs without them, then runs with them, against a sprint spec with planted defects built on the `kopi-uncle` fixture in `.claude/skills/sprintkit-implement/evals/files/`.

## Refreshing

- **pm-skills:** `deliver-prd` and `deliver-edge-cases` are refreshed once, in `../shared-skills/` (see its SOURCE.md). Refresh `utility-pm-critic` here from the same pm-skills version.
- **Spec Kit:** after upgrading spec-kit, run `specify init` in a scratch directory and copy the two generated files here and update the version above.

Edit vendored files only deliberately, and record any edit in the **Local changes** column.
