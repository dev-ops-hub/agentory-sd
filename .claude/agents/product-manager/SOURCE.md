## Notes

- The agent follows `speckit-constitution` with documented deviations (no extension hooks, no template-resolver script, output saved to `planning/constitution.md` instead of `.specify/memory/constitution.md`). Those deviations live in the agent definition, [`../product-manager.md`](../product-manager.md), not in the vendored file.
- Upstream files keep their own headers: pm-skills files carry `license: Apache-2.0` in frontmatter and a `PM-Skills | ... | Apache 2.0` comment; spec-kit files carry `author: github-spec-kit` and their upstream `source:` path.

## Refreshing

- **pm-skills:** copy the same skill folders from a newer plugin version, then update the version above. `deliver-prd`, `deliver-acceptance-criteria`, `deliver-edge-cases` and `develop-adr` are refreshed once, in `../shared-skills/` (see its SOURCE.md); leave their pointer folders here as they are.
- **Spec Kit:** after upgrading spec-kit, re-run `specify init` in a scratch directory and copy the generated `speckit-constitution/SKILL.md` and update the version above.

Edit vendored files only deliberately, and record any edit in the **Local changes** column.
