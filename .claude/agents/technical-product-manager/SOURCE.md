# Source

The `technical-product-manager` agent's skill library (`skills/`) mixes vendored third-party skills and skills written for this repository. Each origin keeps its own license. The agent reads these files on demand; they are not auto-loaded as skills (they live outside `.claude/skills/`).

| Skill | Origin | Version | License | Local changes |
|---|---|---|---|---|
| deliver-acceptance-criteria, deliver-edge-cases | Shared skills: the folders here hold only a `SKILL.md` pointer to `../shared-skills/<name>/`. Origin, version and license are recorded in [`../shared-skills/SOURCE.md`](../shared-skills/SOURCE.md) | pm-skills 2.33.0 | Apache-2.0 | None |
| speckit-specify | [Spec Kit](https://github.com/github/spec-kit) (GitHub), `templates/commands/specify.md`, as generated by `specify init` | specify-cli 1.0.13 | MIT | None; copied verbatim from the generated file |
| writing-sprint-specs (`SKILL.md`, `references/TEMPLATE.md`) | Written for this repository | — | Same terms as this repository | Original |
| tracing-spec-coverage (`SKILL.md`, `scripts/check_spec.py`) | Written for this repository | — | Same terms as this repository | Original |

## How the original skills relate to the vendored ones

- `writing-sprint-specs` is the entry point. It uses `speckit-specify` for spec sections 1-2 and overrides its spec-kit-specific steps (branch creation, `specs/` directory, template resolution, extension hooks, file writes); those overrides are stated in `writing-sprint-specs`, not edited into the vendored file.
- It uses `deliver-acceptance-criteria` for section 4 and `deliver-edge-cases` for section 5, unchanged.
- `tracing-spec-coverage` and its `check_spec.py` are new; they check the template and ID scheme defined by `writing-sprint-specs`.
- Both original skills were developed test-first: baseline agent runs without them, then runs with them, against the `kopi-uncle` fixture in `.claude/skills/sprintkit-implement/evals/files/`.

## Refreshing

- **pm-skills:** `deliver-acceptance-criteria` and `deliver-edge-cases` are refreshed once, in `../shared-skills/` (see its SOURCE.md); nothing to copy here.
- **Spec Kit:** after upgrading spec-kit, run `specify init` in a scratch directory and copy the generated `speckit-specify/SKILL.md` here and update the version above. Re-check that the overrides listed in `writing-sprint-specs` still match the new file's steps.

Edit vendored files only deliberately, and record any edit in the **Local changes** column.
