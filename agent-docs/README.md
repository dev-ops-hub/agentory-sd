# agent-docs

The knowledge base for the sprintkit agents. Agents read it at dispatch time; nothing here is generated by them.

## Layout

| Path | Holds | Read by |
|---|---|---|
| `agent-docs/*.md` | The product itself: the main idea, vision, architecture and domain notes the agents build from. Start with [idea.md](idea.md). | Every agent, and `sprintkit-start` during research |
| `agent-docs/product-manager/` | Knowledge for drafting PRD blocks and the constitution: user research, interview notes, market and competitor facts, house style for PRDs | `product-manager` |
| `agent-docs/product-auditor/` | Knowledge for audits: review checklists, known recurring defects, past audit decisions | `product-auditor` |
| `agent-docs/technical-product-manager/` | Knowledge for sprint specs: technical conventions, interface notes, testing standards | `technical-product-manager` |
| `agent-docs/solution-architect/` | Knowledge for architecture work: platform constraints, existing infrastructure, approved technologies, budget limits, past ADRs | `solution-architect` |
| `agent-docs/ux-designer/` | Knowledge for UI design: brand and taste notes, reference screens, target devices, user research, accessibility needs, past UX decisions | `ux-designer` |

A new agent gets a folder named after its agent file (`.claude/agents/<name>.md` reads `agent-docs/<name>/`).

## Precedence

`planning/` outranks this folder. Where `planning/constitution.md` or the PRD (`planning/product-req-document(PRD).md`) disagrees with a document here, the planning file wins; agents flag the disagreement rather than follow the older text.

## Rules

- Facts and source material only. Agent instructions belong in `.claude/agents/`, method in each agent's `skills/`.
- No secrets, API keys or personal data (constitution VI).
- Each agent folder keeps a `README.md` so the folder stays in git while it is empty.
